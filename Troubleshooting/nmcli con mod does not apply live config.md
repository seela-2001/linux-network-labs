# nmcli con mod does not apply live config

Lab: [[NetworkManager - Modify Connection Not Applied]]

## Problem
After `nmcli con mod <con> ipv4.addresses X`, the interface still has the old IP.

## Diagnosis steps
1. Check the live state: `ip -br a show <dev>`
2. Check the profile: `nmcli -g ipv4.addresses con show <con>`
3. If they differ, the profile changed but was not applied.

## Fix
```bash
nmcli con up <con>
# or, without re-activating:
nmcli dev reapply <dev>
```

---

## Errors hit along the way

### 1. `Error: unknown connection 'dummy-con'`
- **Cause:** typo in the saved name. The profile id was `dymmy-con`.
- **Check:** `nmcli con show` or `sudo cat /run/NetworkManager/system-connections/<file>`
- **Tip:** use the UUID to avoid name typos: `nmcli con mod <uuid> ...`

### 2. `No suitable device found ... eno1 ... has no carrier`
- **Cause:** the profile was bound to a real ethernet port (`interface-name=eno1`) with no cable/link, so it could not activate.
- **Fix:** it activated once `ipv4.method manual` was set. With `auto` (DHCP), NM waits for carrier.
- **Real fix for a lab:** use a **dummy** interface, which does not need a carrier.

### 3. `Cannot change the connection type`
- **Cause:** `connection.type` is immutable after creation.
- **Fix:** delete and recreate with the right type:
```bash
  nmcli con add type dummy ifname dummy0 con-name lab-static ...
```

### 4. Profile generated by netplan
- File name `netplan-NM-<uuid>.nmconnection` means netplan generated it.
- `nmcli` edits on it can be overwritten by `netplan apply` or a reboot. Make persistent changes in `/etc/netplan/`.

### 5. Gateway set to `8.8.8.8`
- The gateway must be a host on the same subnet (e.g. `192.168.50.1`), not a public DNS server.

## Cleanup
```bash
nmcli con delete dummy-con        # leftover profile bound to eno1
nmcli con up static-lab           # bring the real lab ethernet back
```
